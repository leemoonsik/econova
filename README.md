# 라이브모아 — 기본 키보드 바로 위 주문 아이콘 실기기 테스트

## 목표
틱톡/유튜브 등의 댓글창을 눌러 **기본 키보드**가 나타나는 순간,
키보드 **바로 위**에 작은 `🛒 주문` 아이콘을 표시하고,
누르면 이 테스트 앱의 주문 화면을 여는지 확인합니다.

**전용 키보드를 개발하지 않습니다.** 현재 앱에서 사용하는 기본 키보드를 그대로 둡니다.

## 설치
1. Android Studio에서 이 폴더를 프로젝트로 엽니다.
2. Gradle 동기화 후 `app` 모듈을 갤럭시 휴대폰에 실행합니다. (JDK 17)
3. 앱에서 `접근성 서비스 설정 열기`를 누르고 `라이브모아 키보드 위 아이콘 테스트` 서비스를 켭니다.
4. 틱톡 또는 유튜브 라이브 방송을 열고 댓글 입력창을 눌러 기본 키보드를 표시합니다.
5. `🛒 주문` 아이콘이 **키보드 바로 위**에 표시되는지, 누르면 시험 주문창이 열리는지 확인합니다.
6. 댓글창을 닫으면 아이콘이 사라지는지도 확인합니다.

## 테스트 결과 기록
| 시험 앱 | 키보드 나옴 | 주문 아이콘 나옴 | 아이콘 클릭/주문 화면 전환 | 키보드 닫으면 아이콘 사라짐 |
|---|---|---|---|---|
| 일반 문자 입력 앱 | | | | |
| 틱톡 댓글 | | | | |
| 유튜브 댓글 | | | | |
| 라이브모아 내 틱톡/유튜브 | | | | |

## 범위와 유의사항
- **APK가 아닌 소스 프로젝트**입니다. 이 작성 환경에는 Android SDK/Gradle이 없어 APK 빌드 및 실기기 테스트를 하지 못했습니다.
- 접근성 서비스의 `getWindows()`에서 **키보드 윈도우 정보**만 읽고 화면의 문장/댓글 내용은 읽지 않습니다.
- `TYPE_ACCESSIBILITY_OVERLAY`를 사용합니다. 서비스 활성화가 필요합니다.
- 키보드 윈도우 정보를 반환하지 않는 기기나 특정 앱에서는 표시되지 않을 수 있습니다.
- Android 15 등의 화면 상단/하단 인셋 처리, 앱별 레이아웃에 따라 좌표 보정이 필요할 수 있습니다.
- 주문창은 성공 여부를 확인하기 위한 **데모 화면**이며 실제 라이브모아 앱 및 주문 서버와 아직 연결되어 있지 않습니다.
- 이 방식은 일반 화면 오버레이와 다른 접근성 오버레이를 시험하는 것으로, 앱별 제한을 우회할 수 있다고 보장하지 않습니다.
- 실서비스에 도입하는 경우 접근성 기능 사용 목적과 앱 배포 정책 등을 별도 확인해야 합니다.

## GitHub에서 APK 자동 빌드 (추가됨)
1. 이 폴더 전체를 새 GitHub 저장소에 올립니다 (push).
2. 저장소의 **Actions → Build APK** 실행이 끝나면 **Artifacts**에서 `livemoa-ime-overlay-test-apk`를 내려받습니다.
3. 압축을 풀면 `app-debug.apk`가 있습니다. 폰에 설치합니다.
4. Android 13 이상에서 접근성 서비스가 회색으로 막혀 있으면: 설정 → 앱 → 이 앱 → 우측 상단 ⋮ → **제한된 설정 허용** 후 다시 켭니다.

## 수정 내역
- ime_accessibility_service.xml: canRetrieveWindowContent를 false → true 로 변경.
  (flagRetrieveInteractiveWindows는 이 값이 true여야 getWindows()가 키보드 창을 반환합니다. 코드는 여전히 창 위치만 읽고 화면 텍스트는 읽지 않습니다.)
